# New Hire Onboarding Checklist

Before a new hire's first day, their manager files an onboarding ticket with IT and facilities. The ticket triggers laptop imaging, badge issuance, and desk assignment. Filing it fewer than five working days before the start date usually means the laptop is late, so managers are asked to file at offer acceptance.

On day one the new hire completes identity verification with the people team, signs the confidentiality agreement, and enrols in multi-factor authentication. None of the internal systems grant access until multi-factor enrolment is complete, and the people team cannot grant an exception to this rule.

During the first week the new hire is expected to complete four short training modules: security awareness, data handling, the code of conduct, and expense basics. Completion is tracked automatically, and the manager is notified if a module is still outstanding after ten working days.

Access to production systems is deliberately not part of onboarding. Engineers request production access separately once they have shipped their first change and completed the on-call primer. The request goes to the owning team, not to IT, and it is reviewed by a human every time.

At thirty days the manager and the new hire hold a structured check-in covering role clarity, tooling gaps, and any blockers. Notes from that conversation stay between the two of them; only the fact that it happened is recorded.
